# Лабораторная работа №7

Тема: транзакции и оптимизация запросов.

## Описание программы

Программа представляет собой небольшое API для работы с пользователями, курсами, записями на курсы и банковскими счетами. Используется Python, Flask и PostgreSQL. Приложение запускается в Docker.

В работе проверяются транзакции, уровни изоляции, блокировки при одновременном изменении данных, индексы и проблема N+1.

## Запуск проекта

Для запуска базы данных:

```bash
docker compose up -d --wait db
```

Для запуска приложения вместе с базой данных:

```bash
docker compose up -d --build
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

Миграции базы данных запускаются командой:

```bash
python migrate.py up
```

Посмотреть состояние миграций:

```bash
python migrate.py status
```

## Основные функции программы

### Работа с базой данных

`Database.transaction(isolation_level=None)` — открывает транзакцию и возвращает курсор для выполнения SQL-запросов. Если передан уровень изоляции, он устанавливается для этой транзакции. При успешном выполнении вызывается `COMMIT`, при ошибке — `ROLLBACK`.

`Database.close()` — закрывает пул соединений с базой данных.

`CountingCursor.execute(query, vars=None)` — выполняет SQL-запрос и считает количество запросов и время их выполнения. Эти данные используются для поиска медленных запросов и проблемы N+1.

### Переводы между счетами

`TransferService.list_accounts()` — возвращает список счетов с их владельцами, балансом и номером версии. Параметры не принимает.

`TransferService.transfer(from_id, to_id, amount)` — переводит деньги с одного счета на другой.

Параметры:
- `from_id` — ID счета, с которого переводятся деньги;
- `to_id` — ID счета, на который поступают деньги;
- `amount` — сумма перевода.

Перед переводом проверяется наличие счетов и достаточность средств. Строки счетов блокируются через `FOR UPDATE`, чтобы параллельные операции не изменили баланс одновременно. Изменение балансов и добавление записи о переводе выполняются в одной транзакции.

### Запись на курсы

`RegistrationService.register(strategy, course_id, user_id, delay=0.0)` — записывает пользователя на курс.

Параметры:
- `strategy` — способ записи: `naive`, `atomic` или `lock`;
- `course_id` — ID курса;
- `user_id` — ID пользователя;
- `delay` — задержка перед записью, используется в тесте одновременных запросов.

Варианты работы:
- `naive` — сначала проверяет количество свободных мест, затем добавляет запись и уменьшает их количество. При одновременном выполнении возможна ошибка с превышением числа мест;
- `atomic` — уменьшает число мест одним SQL-запросом, только если места ещё есть;
- `lock` — блокирует строку курса через `FOR UPDATE`, проверяет места и выполняет запись.

Повторная запись одного пользователя запрещена ограничением `UNIQUE (user_id, course_id)`.

### Работа с курсами

`CourseService.get_course(course_id)` — возвращает курс по ID, количество свободных мест, версию и число записанных пользователей. Принимает ID курса.

`CourseService.update_course(course_id, title, version)` — меняет название курса. Принимает ID курса, новое название и версию записи, которую видел пользователь. Обновление выполняется только при совпадении версии. Если данные уже изменил другой запрос, возвращается конфликт `VERSION_CONFLICT`.

`CourseService.list_with_students(limit, mode)` — возвращает список курсов и до пяти последних записавшихся на каждый курс.

Параметры:
- `limit` — максимальное количество курсов;
- `mode` — режим запроса: `naive` или `joined`.

В режиме `naive` для каждого курса отдельно загружается список студентов. В режиме `joined` используется один SQL-запрос с `LEFT JOIN LATERAL`. Второй вариант уменьшает количество обращений к базе данных.

### Проверка входных данных и ошибок

`get_json_object()` — получает JSON из тела запроса и проверяет, что передан объект.

`int_field(data, name, minimum)` — проверяет целочисленное поле и минимальное значение.

`str_field(data, name, min_len, max_len)` — проверяет строку и её длину.

`amount_field(data)` — проверяет сумму перевода. Значение должно быть положительным, не больше 1 000 000 и иметь не более двух знаков после запятой.

`query_int(name, default, minimum, maximum)` — получает целое число из параметров URL и проверяет допустимый диапазон.

Ошибки API возвращаются в JSON с кодом ошибки, сообщением, дополнительными данными и ID запроса.

### Миграции

Файл `migrate.py` применяет SQL-файлы из папки `migrations`.

- `python migrate.py status` — показывает применённые и ожидающие миграции;
- `python migrate.py up` — применяет новые миграции;
- `python migrate.py down` — отменяет последнюю применённую миграцию.

Миграция `001_schema` создаёт таблицы. `002_indexes_basic` добавляет основные индексы. `003_indexes_advanced` добавляет функциональный и частичный индексы.

### Вспомогательные скрипты

`python -m scripts.seed` — очищает таблицы и добавляет тестовые данные: 200 000 пользователей, 100 курсов, 300 000 записей и 3 счета. После добавления данных выполняется `ANALYZE`.

`python -m scripts.tx_demo atomicity` — показывает разницу между переводом без транзакции и переводом с транзакцией.

`python -m scripts.tx_demo savepoint` — проверяет работу `SAVEPOINT` и откат части транзакции.

`python -m scripts.tx_demo isolation` — сравнивает уровни изоляции `READ COMMITTED` и `REPEATABLE READ`.

`python -m scripts.tx_demo deadlock` — показывает взаимную блокировку и проверяет, как помогает одинаковый порядок блокировки строк.

`python -m scripts.race_demo` — запускает одновременную запись 30 пользователей на курс с 10 местами. Сравнивает стратегии `naive`, `atomic` и `lock`.

`python -m scripts.explain` — выполняет тестовые запросы с `EXPLAIN ANALYZE` и выводит время выполнения и тип сканирования таблиц или индексов.

## API

`GET /accounts` — получить список счетов.

`POST /transfers` — выполнить перевод. JSON-параметры: `from_account`, `to_account`, `amount`.

`GET /courses?mode=joined&limit=20` — получить курсы и студентов. `mode` принимает `naive` или `joined`, `limit` — число курсов от 1 до 200.

`GET /courses/<course_id>` — получить информацию о курсе по его ID.

`PUT /courses/<course_id>` — изменить название курса. JSON-параметры: `title` и `version`.

`POST /courses/<course_id>/register?strategy=atomic` — записать пользователя на курс. JSON-параметр: `user_id`. Параметр `strategy` принимает `naive`, `atomic` или `lock`.

В ответах API также передаются заголовки `X-DB-Queries` и `X-DB-Time-Ms`. Они показывают количество SQL-запросов и время работы с базой данных.

## Итог

В лабораторной работе проверена работа транзакций и отката изменений, уровней изоляции и блокировок. Для записи на курс сравнивались три способа обработки одновременных запросов. Также была реализована оптимистическая блокировка через поле `version`.

Для ускорения запросов добавлены индексы, а проблема N+1 проверена сравнением режимов `naive` и `joined`. Количество запросов при получении списка курсов со студентами удалось уменьшить со 101 до 1. Для анализа использовались `EXPLAIN ANALYZE`, `pg_stat_statements` и журнал PostgreSQL.
